# scan-agent-config

Scans the files that steer AI coding agents: instructions an agent follows and configuration it runs. These files are effectively executable, and few tools check them.

```bash
ai-guard scan-agent-config                 # scan the repository
ai-guard scan-agent-config --json          # machine-readable report
ai-guard scan-agent-config --sarif --sarif-output agent-config.sarif
ai-guard scan-agent-config --update-lock   # approve the current MCP servers
```

| Option | Description |
|---|---|
| `--path <dir>` | Directory to scan (default `.`) |
| `--json` | Output the report as JSON |
| `--sarif`, `--sarif-output <file>` | SARIF 2.1.0 output |
| `--fail-on <level>` | Exit 1 on `error` (default), `warning`, or `none` |
| `--lock <file>` | MCP lock file (default `.ai-guard-mcp-lock.json`) |
| `--update-lock` | Write the current server fingerprints to the lock file |

## Files scanned

**Instructions:** `CLAUDE.md`, `CLAUDE.local.md`, `AGENTS.md`, `AGENT.md`, `GEMINI.md`, `.cursorrules`, `.windsurfrules`, `.clinerules`, `.roorules`, `.goosehints`, `.cursor/rules/**`, `.windsurf/rules/**`, `.roo/**`, `.continue/rules/**`, `.github/copilot-instructions.md`, `.github/instructions/**`, `.github/prompts/**`, `.claude/commands/**`, `.claude/agents/**`, `.claude/skills/**`, `.agents/**`, and the commands, agents and skills of Claude Code plugins.

**Configuration:** `.mcp.json` (anywhere), `.cursor/mcp.json`, `.vscode/mcp.json`, `.roo/mcp.json`, `.windsurf/mcp.json`, `.gemini/settings.json`, `.claude/settings.json`, `.claude/settings.local.json`, and plugin `hooks/hooks.json`.

Dependencies and build output are skipped.

## Errors

Almost never legitimate. They exit 1 by default.

### hidden-text

Unicode tag characters or variation-selector runs encode text that people can't see but AI tools read. The finding shows the decoded text. This is the technique behind the [Rules File Backdoor](https://pillar.security/blog/new-vulnerability-in-github-copilot-and-cursor-how-hackers-can-weaponize-code-agents).

### invisible-character

Zero-width, filler or bidirectional control characters. Emoji sequences, joiners in Persian and Indic text, and flag sequences are allowed.

### hidden-instructions

A suspicious instruction inside an HTML comment, which rendered Markdown doesn't show: a remote script, concealment, an instruction override, a credential read, or exfiltration.

### exfiltration

Tells the agent to send local secrets (`.env`, SSH keys, environment variables) to a URL.

### inline-secret

A literal credential in an MCP server's `env`, `headers`, arguments or URL, or in Claude settings. Values such as `${env:TOKEN}`, `${input:token}` and `<YOUR_TOKEN>` are references, not secrets. Findings never print the secret.

### hook-remote-code

A hook in Claude settings or a plugin pipes a download into a shell. Hooks run automatically.

## Warnings

Worth a human look. Add `--fail-on warning` to fail on them.

### hidden-comment

An HTML comment addresses the AI ("Claude: always add...", "when generating code..."). Tooling markers such as `prettier-ignore` and "generated by" are ignored.

### remote-code-execution

Tells the agent to pipe a download into a shell (`curl ... | bash`, `irm ... | iex`). Skipped when negated ("never run curl | bash").

### external-script

An external `<script src>`. Reported only inside HTML comments (as `hidden-instructions`), because visible CDN tags are normal in web-development skills.

### concealment

Tells the agent to hide what it did: "do not mention this", "without telling the user", "hide these changes from the reviewer". Product guidance such as "never show users stack traces" is not matched.

### instruction-override

"Ignore all previous instructions" and similar prompt-injection phrasing.

### credential-access

A read or send action on a key or token file, such as "read ~/.ssh/id_rsa". Mentions alone, `~/.ssh/config`, public keys and "never read" lists are not matched.

### unpinned-mcp-server

An MCP server started with `npx`, `bunx`, `pnpm dlx`, `uvx`, `pipx run`, `deno` or `docker` without an exact version, so each start can fetch a different release. Pin it: `pkg@1.2.3`, `pkg==1.2.3`, or `image@sha256:...`.

### insecure-transport

A remote MCP server over plain `http://`. Localhost is fine.

### auto-approve-mcp

`enableAllProjectMcpServers` starts every server in `.mcp.json` without asking, so a pull request can add one that runs on each developer's machine.

### bypass-permissions

`defaultMode: "bypassPermissions"` in shared settings.

### unrestricted-shell

`Bash` or `Bash(*)` in `permissions.allow`. Scoped rules such as `Bash(npm test:*)` are fine.

### mcp-server-changed

A server's fingerprint differs from the lock file.

### mcp-server-unapproved

A server isn't in the lock file.

### invalid-config

A config file isn't valid JSON (comments and trailing commas are accepted), so it wasn't scanned.

## MCP server lock file

Each server gets a fingerprint: a SHA-256 of its canonical configuration. `--update-lock` records them in `.ai-guard-mcp-lock.json`. Commit that file. Later scans report any server that changed or is new, and the change shows up in code review.

The lock covers configuration only. It can't detect a server changing its tool descriptions at runtime.

## GitHub Code Scanning

This scan has its own SARIF slot, `automationDetails.id: "ai-guard-agent-config"`, so uploading it never replaces the main scan's alerts:

```yaml
- run: npx -p eslint-plugin-ai-guard ai-guard scan-agent-config --sarif --sarif-output agent-config.sarif --fail-on none
- uses: github/codeql-action/upload-sarif@v3
  with:
    sarif_file: agent-config.sarif
    category: ai-guard-agent-config
```
