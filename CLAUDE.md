## SARIF Integration

SARIF output is generated by `cli/utils/sarif.ts`. Critical rules:

- **No `uriBaseId`** — GitHub Code Scanning cannot resolve custom base ID mappings.
  Artifact URIs MUST be repository-relative POSIX paths (`src/api.ts`, not `/home/runner/.../src/api.ts`).
- **`automationDetails.id: "ai-guard"`** — must never change; changing it orphans all existing alerts.
- **`partialFingerprints["ai-guard/v1"]`** — SHA-256 of `ruleId:uri:line:message`.
  Must be deterministic; no timestamps, no random values, no absolute paths.
- **`category: ai-guard`** on `upload-sarif` step — links to a persistent Code Scanning slot.

To debug SARIF path resolution: `ai-guard run --sarif --debug-sarif-paths`
To debug persistence identity: `ai-guard run --sarif --debug-sarif-persistence`

## Async Reliability Rules

**Never** pass async callbacks to array methods:
```typescript
// ❌ Returns Promise[], not values
const results = ids.map(async (id) => await fetchUser(id));

// ✅ Correct
const results = await Promise.all(ids.map((id) => fetchUser(id)));
```

**Never** use sequential await in loops when parallel execution is safe:
```typescript
// ❌ Sequential — O(n) latency
for (const order of orders) { await sendEmail(order.email); }

// ✅ Parallel
await Promise.all(orders.map(async (order) => sendEmail(order.email)));
```

**Never** call an async function without await or `.catch()`:
```typescript
// ❌ Floating promise — errors are silently swallowed
sendNotification(userId);

// ✅
await sendNotification(userId);
// or, for intentional fire-and-forget:
void sendNotification(userId);
```

**Never** declare a function `async` if it never uses `await`.

## Error Handling Rules

**Never** generate empty catch blocks:
```typescript
// ❌
try { await fetchUser() } catch (e) {}

// ✅
try { await fetchUser() } catch (e) {
  logger.error('fetchUser failed', e);
  throw e;
}
```

**Never** catch, log, and rethrow the same error without adding context:
```typescript
// ❌
catch (e) { console.error(e); throw e; }

// ✅
catch (e) { throw new Error('fetchUser failed', { cause: e }); }
```

## Security Rules

**Never** hardcode secrets, API keys, tokens, or passwords:
```typescript
// ❌
const apiKey = 'sk-prod-abc123';

// ✅
const apiKey = process.env.API_KEY;
```

**Never** build SQL queries with string concatenation or template literals:
```typescript
// ❌ SQL injection risk
db.query('SELECT * FROM users WHERE id = ' + req.params.id);

// ✅
db.query('SELECT * FROM users WHERE id = $1', [req.params.id]);
```

**Never** use `eval()` or `new Function()` with dynamic or user-supplied strings.

**Never** call `JSON.parse()` on `req.body`, `req.query`, or `req.params` without schema validation.

**Always** add authentication middleware before route handlers:
```typescript
// ❌
router.get('/admin/users', getUsers);

// ✅
router.get('/admin/users', requireAuth, getUsers);
```
